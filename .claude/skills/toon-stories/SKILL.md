# Мульты кодом (toon-stories)

Этот скилл ведёт человека от идеи до готового mp4 для YouTube. Всё в кадре рисует код: SVG в Remotion для 2D, Three.js для 3D. Нейросети для картинок не нужны, всё бесплатно. Рядом с этим файлом лежит проверенный стартовый набор `kit/` и справочники `references/`:
- `references/SCRIPT.md` — ниши, банк фактов, арка истории, приёмы, генератор идей, темп и словарь кадров, главы, серии;
- `references/STYLE.md` — три варианта персонажа, темы света, пресеты, разбор референса, чек-лист «арт-директора»;
- `references/ENGINE.md` — как устроен движок, звук и музыка, проверка кадров.

Что получается:
- персонаж на выбор: мультяшная кукла с суставами или стикмен; моргает, дышит, пугается, берёт предметы;
- живая локация: снег за окном, пар над кружкой, качается лампа; свет как в кино;
- инфографика: каждая цифра из текста появляется на экране (счётчик, сравнение, чертёж);
- крупные субтитры по одному слову, плашки времени, титры глав, концовка с призывом;
- голос, тональный фон или своя музыка, которая сама стихает под голосом, громкость −14 LUFS.

## Как говорить с пользователем (всегда)

1. Пиши простыми словами и нумерованными шагами, без жаргона. Пользователь может быть новичком: не пиши «бандл», «IK», «composition» без пояснения в скобках.
2. Задавай по одному решению за раз. У каждого вопроса — 2–4 варианта, первый «(рекомендую)». Если есть инструмент вопросов с кнопками (AskUserQuestion), используй его. Если вариантов больше четырёх, покажи четыре самых подходящих, остальное — через «другое».
3. Если пользователь торопится или пишет «на твой вкус», бери варианты «(рекомендую)» и скажи одной строкой, что выбрал.
4. Проверка до рендера, всегда по порядку: **стоп-кадры → превью 30 с → «ок» → полный рендер.** Картинки показывай прямо в чат. Если пользователь забраковал вид, не переделывай молча: предложи 2–3 варианта, он выбирает, потом рендер.
5. Новый персонаж или новый стиль — сначала тест 4–5 секунд, потом весь ролик.
6. Не удаляй и не двигай файлы пользователя. Всё временное клади в папку `_tmp/` студии.
7. Береги компьютер: рендер с низким приоритетом, 2 потока, один тяжёлый рендер за раз (`scripts/render.mjs` делает это сам).
8. Ключи (ElevenLabs и любые другие) храни только в файле `.env` студии. Никогда не печатай ключ в чат и не вставляй его в код.
9. После каждого этапа обновляй `_tmp/<ролик>/ПРОГРЕСС.md`: что сделано, пути, решения пользователя, следующий шаг. Если контекст сжался, сначала прочитай этот файл и продолжай с отмеченного места.

## Дорожная карта

### Шаг 0. Скилл получен одним файлом?
Если рядом с этим SKILL.md нет папки `kit/`, а пользователь дал файл `toon-stories (всё в одном).md`, разложи его по инструкции в начале того файла: там есть готовый скрипт распаковки. Потом продолжай с шага 1.

### Шаг 1. Проверить компьютер и поставить недостающее
Сначала спроси одной строкой: «Ты уже ставил Node.js, Python, FFmpeg и Remotion или начинаем с нуля?» Ответ — лишь подсказка, всё равно проверь сам:

```bash
node -v ; npm -v ; python --version ; ffmpeg -version ; python -c "import edge_tts, numpy; print('py ok')"
```
На macOS и Linux вместо `python` может быть `python3` (и `pip3`). Ещё посмотри, нет ли в текущей папке `package.json` с `remotion` или `three`. Если есть, это готовый проект: спроси, класть ли мультики в него (папка `src/toon/`) или делать отдельную студию (рекомендую отдельную).

Покажи пользователю табличку «есть / нет» и спроси: «Поставить недостающее? (рекомендую)». Только после «да» ставь:

| Что | Windows | macOS | Linux |
|---|---|---|---|
| Node.js 20+ | `winget install OpenJS.NodeJS.LTS` | `brew install node` | `sudo apt install nodejs npm` (или nvm) |
| Python 3.10+ | `winget install Python.Python.3.12` | `brew install python` | обычно уже есть |
| FFmpeg | `winget install Gyan.FFmpeg` | `brew install ffmpeg` | `sudo apt install ffmpeg` |
| Python-пакеты | `pip install edge-tts numpy` | то же | то же |
| Свой голос (по желанию) | `pip install faster-whisper` | то же | то же |

После установки через winget открой новый терминал, чтобы команды нашлись.

Создай студию:
1. Скопируй всё из `kit/` в новую папку, например `toon-studio` в домашней папке. Если проект уже есть, перенеси только `src/toon` и `scripts`, добавь композиции из `kit/src/Root.tsx` в его Root и зависимости из `kit/package.json`.
2. В папке студии выполни `npm install`. Это скачает Remotion, React и Three.js — около 300 МБ, 2–5 минут. Предупреждение `npm warn allow-scripts … esbuild` не мешает, его можно пропустить.
3. Проверка «всё работает», пара минут. Команды из папки студии (в PowerShell `cp` тоже работает):
   ```bash
   python scripts/tts.py src/toon/episodes/example.lines.json public/example
   cp public/example/voice.json src/toon/episodes/example.voice.json
   python scripts/sfx.py public/example/voice.wav public/example/voice.json src/toon/episodes/example.cues.json public/example public/example/mix.wav
   node scripts/render.mjs stills Example _tmp/check 60 170 330
   ```
   Если голос Дмитрий не ответил, скрипт сам возьмёт Светлану: это нормально. Покажи пользователю кадр: «Вот так выглядит пример. Делаем свой ролик?»

### Шаг 2. Анкета канала (по одному вопросу)
Ответы запиши в `_tmp/<ролик>/ПРОГРЕСС.md`, а то, что относится к каналу целиком, — в `CHANNEL.md` студии (пригодится для следующих роликов; если файл уже есть, прочитай его и спрашивай только новое).
1. **Ниша:** «Что если» (рекомендую) / выживание, блэкаут / правила / странные факты / история / своё. Формулы ниш — в `references/SCRIPT.md`, раздел 1.
2. **Про что канал:** одной фразой — про что, кто зритель, язык (русский по умолчанию).
3. **Один ролик или серия:** один ролик (рекомендую для начала) / серия. Для серии заведи `SERIES.md`: герой, правила мира, список серий (SCRIPT.md, раздел 10).
4. **Формат:**
   - короткий 9:16 до 60 с для Shorts, Reels, TikTok (рекомендую для первого раза) — около 130 слов;
   - длинный 16:9 для YouTube, 8–12 мин с главами — около 130 слов на минуту, 10 мин ≈ 1300 слов;
   - тест 15–30 с — 35–65 слов.
5. **Тема:** придумай сам (рекомендую: 10 идей списком, на «ещё» — следующие 10) / своя тема / готовый текст.
6. **Что уже вышло:** «Пришли названия своих роликов, чтобы не повторяться» / «канал новый».
7. **Образцы текста** (по желанию): сценарии или субтитры роликов, которые нравятся (`.txt`, `.srt`). Беру только манеру — ритм, «ты», крючки, — а не содержание (SCRIPT.md, раздел 7).

### Шаг 3. Персонаж и стиль
1. **Персонаж** (подробно — STYLE.md, раздел 1):
   - (а) наш мультяшный персонаж — кукла с кожей, причёской и пальцами (рекомендую для блэкаута и драмы);
   - (б) стикмен — круглая чёрная голова с подсветкой по краю, простые глаза и рот, яркое худи, тонкие руки и ноги с суставами (рекомендую для «что если» и фактов);
   - (в) по референсу — «скинь 1–3 скриншота ролика, который нравится, или опиши словами». Разбери по чек-листу STYLE.md, раздел 4, запиши `STYLE-CARD.md`, покажи и спроси «так?». Потом подгони `Look`, стикмена и тему.
2. **2D или 3D** (только для варианта «а»): 2D (рекомендую) — выразительная мимика, быстрый рендер; 3D — объём, мимика проще, рендер дольше.
3. **Тема света:** `dusk` (рекомендую) / `night` / `gold` / `neon` / `fairytale` (STYLE.md, раздел 2), или пресет оттуда же.
4. **Тест 4–5 секунд.** Одна сцена, герой в позе, свет темы, субтитр с фразой-крючком. Покажи 2–3 стоп-кадра и спроси «ок / что поменять». Только после «ок» переходи к сценарию.

Карточку стиля храни в `STYLE-CARD.md` студии: следующий ролик начинай с неё.

### Шаг 4. Голос, звук, компьютер
1. **Голос:**
   - бесплатно, edge-tts (рекомендую для старта). RU: `ru-RU-DmitryNeural` (мужской), `ru-RU-SvetlanaNeural` (женский). Другие языки: `python scripts/tts.py --voices en`;
   - ElevenLabs: живые голоса и клоны, нужен ключ. Объясни коротко: elevenlabs.io → Profile → API Keys → Create. Ключ пусть сам впишет в файл `.env` студии строкой `ELEVENLABS_API_KEY=...`, а в чат не присылает. Список голосов: `python scripts/tts.py --voices elevenlabs`;
   - свой голос: пользователь читает готовый текст на телефон или микрофон и кладёт файл в студию. Тайминги слов достанет `scripts/align.py` (шаг 8). Нужен `pip install faster-whisper`; модель скачается сама при первом запуске (около 0,5 ГБ).
2. **Звук:** тональный фон и эффекты (рекомендую) / своя музыка (файл трека в `public/music/`; пусть пользователь берёт только трек, который можно использовать на YouTube) / только голос.
3. **Компьютер:** слабый, средний или мощный. Это число потоков рендера: `TOON_THREADS=1 / 2 / 4`, по умолчанию 2.

### Шаг 5. Сценарий
Пиши по `references/SCRIPT.md`:
1. **Банк фактов:** 5–10 проверенных фактов с источниками; фантазия отдельно от фактов. Сохрани в `_tmp/<ролик>/ФАКТЫ.md`, покажи таблицей.
2. **План по арке** (5–10 строк): крючок → базовая цифра и одно правило силы → монтаж последствий → скрытая цена → эмоциональный момент с посаженной деталью → выбор «или–или» → развязка → «Это вообще реально?» → крючок на следующую серию → призыв подписаться и написать мнение. Для шорта — короткая версия арки из SCRIPT.md. Спроси «ок?».
3. **Текст**: на «ты», фразы по 3–8 слов, «факт — а ты?», контрасты. Посчитай слова и сверь с бюджетом из шага 2. Для длинного ролика — главы.

Покажи текст и спроси «ок / поправить». Сразу подготовь `lines.json`, по одной фразе на строку:
- в тексте для голоса нет тире (edge-tts на них запинается);
- числа и годы написаны словами;
- для субтитров можно задать отдельный текст с цифрами и многоточиями (`sub`).

### Шаг 6. Раскадровка
Таблица: № кадра, время, на какой фразе начинается, тип кадра (общий, средний, крупный, вставка, инфографика, чертёж, титр, концовка — SCRIPT.md, раздел 8), локация, что делает персонаж, какая цифра на экране, свет и тема, переход. Новый кадр каждые 2–3,5 с: на 30 с около 10 кадров, на 10 мин — 150–250. Для длинного ролика покажи раскадровку по главам. Спроси «ок?».

### Шаг 7. Озвучка (edge-tts или ElevenLabs)
```bash
python scripts/tts.py _tmp/<ролик>/lines.json public/<ролик>
cp public/<ролик>/voice.json src/toon/episodes/<ролик>.voice.json
```
- Скрипт сохраняет время каждого слова. По этим временам анимируются субтитры, свет, цифры и игра персонажа.
- Если edge-tts трижды подряд не отдал звук, скрипт сам переозвучит весь ролик запасным голосом: Дмитрий ↔ Светлана. Голоса в одном ролике не смешивай. Сообщи пользователю одной строкой.
- Если молчит и запасной голос, предложи на выбор: подождать 10 минут, взять ElevenLabs или записать свой голос (шаг 8).

### Шаг 8. Свой голос (если выбран)
1. Попроси записать текст из `lines.json` целиком, спокойно, с паузами между фразами. Подойдёт любой файл: wav, mp3, m4a, видео с телефона.
2. Тайминги слов:
   ```bash
   python scripts/align.py "<запись>" public/<ролик> --lines _tmp/<ролик>/lines.json
   cp public/<ролик>/voice.json src/toon/episodes/<ролик>.voice.json
   ```
   Получатся те же `voice.wav` и `voice.json`, что у озвучки: дальше всё одинаково. Язык по умолчанию русский (`--lang en` для английского), модель `small` (`--model base` — быстрее, `--model medium` — точнее).
3. Если скрипт написал «matched меньше 80 %», запись и текст расходятся: спроси, тот ли файл, или перезапусти без `--lines` (тогда фразы возьмутся из распознавания).
4. Если faster-whisper не стоит, скрипт сам подскажет команду установки: `pip install faster-whisper`.

### Шаг 9. Сборка ролика
Как устроен движок и как его расширять — в `references/ENGINE.md`. Коротко:
1. Скопируй `episodes/exampleAct.ts` и `Example.tsx` (или `Example3D.tsx`, или пример со стикменом `StickExample`) под имя ролика. Зарегистрируй композицию в `src/Root.tsx`.
2. **BEATS**: каждое событие привязано к слову (`W('гаснет')`) или к началу фразы (`L(5).start`). Ни одной «магической» секунды.
3. **Кадры** — отдельные компоненты. Ролик выбирает кадр по времени, на стыке ставит переход (`cut`, `flash`, `dip`, `whip`, `zoom`).
4. **Персонаж**: кукла — поза `Pose` и лицо `Face`, внешность — `Look` в `rig/style.ts`; стикмен — позы `POSES`, эмоции `EXPR`, плавный переход `blendPose`, ходьба `walkCycle`.
5. **Инфографика**: каждая названная цифра — на экран (`Counter`, `Compare`, `NumberCard`, `BlueprintCard`), титры глав — `TitleCard`, концовка — `EndScreen`.
6. **Локации**: готовы кухня ночью, окно с городом и улицей, крупный план телефона, свеча. Новые строй по рецепту из ENGINE.md: фон → середина → передний план, у всего «живые» мелочи.
7. **Свет и тема** — слои поверх сцены (`scene/Light.tsx`) и тема из `lib/fx.ts`.
8. **Текст** всегда поверх всех объектов. Субтитры внизу, для 9:16 — `bottom≈420`.

### Шаг 10. Стоп-кадры, лист кадров и строгая проверка
```bash
node scripts/render.mjs stills <Ролик> _tmp/<ролик>/кадры 60 300 600
node scripts/render.mjs sheet <Ролик> _tmp/<ролик>/лист.png 5
```
- `stills` — полноразмерные кадры по номерам (кадр = секунда × 30).
- `sheet` — один PNG: кадр каждые 5 секунд, по 320 px. Для длинного ролика бери 10–15 секунд. Так виден весь ролик и не забивается контекст.

Проверь сам по чек-листу «арт-директора» из `references/STYLE.md`: пропорции, кисти, ноги; читается ли силуэт; не пересвечено ли; не закрыт ли текст; цифры совпадают с голосом; кадры чередуются; нет ли «халтуры». Исправь найденное. Потом покажи пользователю 3–4 кадра или лист и спроси, что поменять.

### Шаг 11. Звук и музыка
Опиши звук в `episodes/<ролик>.cues.json` (подробно — ENGINE.md, раздел «Звук и музыка»):
1. **План музыки по актам:** спокойно (крючок, базовая цифра) → напряжение (последствия, цена) → удар (выбор «или–или») → разрешение (развязка, призыв). Каждый акт — свой аккорд-подложка (`pads`), смена на сильном слове.
2. **Эффекты** (`events`): щелчок, глухой удар, нотки на появление цифр, тональный «проезд».
3. **Своя музыка** (по желанию): `"music": {"file": "public/music/трек.mp3", "gain": 0.2}` — путь от папки студии (или от папки `cues.json`).
4. Подложки и музыка **сами стихают под голосом** на 7–9 дБ (плавно, без «качания»). Настройка: `"duck": {"db": 7, "music_db": 9}`, выключить — `"duck": false`.

Время задавай словом из озвучки: `"@гаснет+0.2"`, `"line:4-0.15"`, `"end"`. Тогда после переозвучки ничего не съедет.
```bash
python scripts/sfx.py public/<ролик>/voice.wav public/<ролик>/voice.json src/toon/episodes/<ролик>.cues.json public/<ролик> public/<ролик>/mix.wav
```
Звук только тональный: никаких синтетических шумов (дождь, ветер, шипение слышатся как помехи). Итог −14 LUFS, пик −1,5 дБ.

### Шаг 12. Превью и полный рендер
1. **Превью** — первые 30 секунд в половинном размере, около минуты работы:
   ```bash
   node scripts/render.mjs preview <Ролик> _tmp/<ролик>/превью.mp4
   ```
   Отдай пользователю файл и спроси «ок / что поменять». Можно задать другую длину: `... превью.mp4 15`.
2. **Полный рендер** — только после «ок»:
   ```bash
   node scripts/render.mjs render <Ролик> out/<ролик>.mp4
   ```
   Ориентир на обычном ПК без видеокарты: 2D около 2 с рендера на секунду ролика, 3D около 3 с. 10 минут 2D — примерно 20–30 минут: запусти в фоне и скажи пользователю, сколько ждать.
3. После рендера проверь:
   - громкость: `ffmpeg -i out/<ролик>.mp4 -af ebur128=peak=true -f null -` (I ≈ −14);
   - длительность совпадает с озвучкой, звук есть;
   - 3–4 кадра из готового файла: `ffmpeg -ss 5 -i out/<ролик>.mp4 -frames:v 1 кадр.png`.

### Шаг 13. Сдача
1. Один путь к mp4 и 2–3 стоп-кадра картинками прямо в чат.
2. Что получилось и что не проверено, например «звук на слух не слушал».
3. Спроси оценку и что докрутить.
4. По просьбе предложи название, описание (для длинного — с метками глав) и теги. Источники фактов из `ФАКТЫ.md` — в описание.
5. Допиши в `STYLE-CARD.md`, `CHANNEL.md` (и `SERIES.md` для серии) и `ПРОГРЕСС.md` 5–10 строк: что сработало, что пользователь поправил, какое название вышло. Следующий ролик начинай с этого.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `NoAudioReceived` от edge-tts | Временный сбой сервиса: скрипт повторит и сменит голос. Не вставляй тире в текст. |
| `faster-whisper is not installed` | `pip install faster-whisper`, потом команду ещё раз. |
| `matched` меньше 80 % в align.py | Запись не совпадает с текстом: тот ли файл? Иначе запуск без `--lines`. |
| `music file not found` | Путь к треку считается от папки `cues.json` или от папки студии. Проверь имя файла. |
| В кадре вместо 3D белый или чёрный экран | Рендерить с `--gl=angle` (render.mjs делает так по умолчанию). На Linux без видеокарты — `TOON_GL=swangle`. |
| Шрифт с кириллицей не загрузился | Нужен интернет при рендере (Google Fonts) или локальный шрифт через `@font-face` и `staticFile`. |
| Персонаж в темноте — чёрное пятно | Добавить «свет луны спереди» (rim) и ослабить слой ночи. Для стикмена — подсветка по краю и светлый фон за силуэтом. |
| Лицо пересвечено в 3D | Лампу выше, точечный свет слабее, порог bloom около 0,98. |
| Ноги или руки скрестились | Поменять сторону сгиба (`bend`) или развести целевые точки. |
| Компьютер тормозит | `TOON_THREADS=1`, закрыть превью Remotion Studio. |
| «Рендери быстрее», «используй больше мощности», «на полную» | Подними потоки: `TOON_THREADS=4…8` (не больше числа ядер минус 2). Предупреди одной строкой, что компьютер будет занят сильнее. Низкий приоритет оставь: если пользователь работает, его программы всё равно быстрее. Обратно — «экономь ПК» → `TOON_THREADS=1` или 2. Выбор запиши в `CHANNEL.md`, чтобы он действовал и в следующих роликах. |
| Пути с кириллицей или пробелами ломают команду | Брать путь в кавычки. В PowerShell использовать `"..."`, а не `'...'`, если внутри переменные. |

## Как пользователю докрутить скилл под себя
Скилл — это обычные текстовые файлы, Claude правит их по просьбе. Хорошие просьбы:
- «Добавь в скилл второго персонажа: девушка, рыжее каре, зелёный свитер» — новый `Look` и вариант причёски в `Head.tsx`, запись в STYLE.md.
- «Стикмену — жёлтая кепка и очки» — параметры стикмена и фирменный цвет в `STYLE-CARD.md`.
- «Сделай локацию подъезд / улица / метро» — новый файл в `scene/` по рецепту из ENGINE.md.
- «Запомни мой стиль: вот 3 скрина» — карточка стиля становится пресетом в STYLE.md.
- «Хочу всегда ElevenLabs, голос такой-то» или «всегда мой голос» — поменять умолчание в шаге 4.
- «Субтитры жёлтые с обводкой, плашка справа» — правка `ui/Captions.tsx` и правило в STYLE.md.
- «Сделай серию из 5 роликов про…» — `SERIES.md` с героем, правилами мира и списком серий.

После удачного ролика проси Claude: «допиши в скилл, что сработало». Так скилл учится на каждом ролике.

## Карта набора `kit/`
- `scripts/tts.py` — озвучка (edge-tts / ElevenLabs) и тайминги слов. `scripts/align.py` — тайминги для своего голоса (faster-whisper). `scripts/sfx.py` — звук, своя музыка, приглушение под голос, громкость. `scripts/render.mjs` — стоп-кадры, лист кадров, превью и рендер с низким приоритетом.
- `src/toon/lib/anim.ts` — плавности, пружины, моргание, двухзвенный IK (расчёт локтя по кисти). `lib/poses.ts` — позы и эмоции стикмена. `lib/fx.ts` — темы света и переходы.
- `src/toon/rig/` — персонажи 2D: `style.ts` (контур, палитра `Look`), `Head.tsx` (голова 2.5D), `Character.tsx` (кукла), `Stickman.tsx` (стикмен).
- `src/toon/scene/` — локации 2D: `Kitchen.tsx` (кухня, стол, лампа, свеча), `City.tsx`, `WindowView.tsx` (окно, улица, двор `Yard.tsx`), `Fridge.tsx`, `SinkInsert.tsx`, `PhoneInsert.tsx` и `PhoneChat.tsx` (экран телефона, переписка), `Stairwell.tsx` (подъезд), `Elevator.tsx` (лифт), `Rooftop.tsx` (крыша, небо, город по теме), `Light.tsx` (свет), `FxLayers.tsx` (цвет темы, переходы).
- `src/toon/ui/` — `Captions.tsx` (субтитры по словам и плашка времени), `Info.tsx` (счётчик, сравнение, карточка цифры, чертёж, титр, концовка).
- `src/toon/three/` — 3D: `toon3d.tsx` (мультяшные материалы и контур), `Hero3D.tsx` (персонаж), `Kitchen3D.tsx` (комната, город, свет).
- `src/toon/episodes/` — примеры роликов: кукла в 2D, 9:16 и 3D, стикмен (`StickExample`). Копируй их для своих роликов.
